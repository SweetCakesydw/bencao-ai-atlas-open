# 系统架构概览

本文档只描述项目的高层架构，不提供生产端点、提示词、业务 Skill、数据结构或安全配置。

## 系统分层

### 交互层

网站由 Vercel 托管，负责页面导航、图谱交互、流式进度展示和结果可视化。

### 服务编排层

AI 功能统一通过 Supabase Edge Functions 进入服务端。该层负责：

- 请求和额度校验。
- 场景化业务流程编排。
- 私有本草数据召回。
- 千问模型调用。
- 结构化输出校验、修复和事实回填。
- 向前端返回可渲染的流式事件。

### 数据与规则层

完整本草数据、版本化业务 Skill、模型规范和运行时安全规则保留在私有环境。浏览器不直接获取这些内容。

## 一次 AI 请求的概念流程

1. 浏览器提交问题和最小必要的场景上下文。
2. Edge Function 完成身份、额度和输入边界校验。
3. 系统从私有本草数据中组织与当前问题相关的证据。
4. 服务端使用统一模型、业务 Skill 和结构规范调用千问。
5. 程序校验模型输出，并回填可追溯的原书事实。
6. 前端将结构化数据渲染为图谱、卡片或文本回答。

## 凭证模式

官方托管与用户自有 Key 使用同一服务端流程。两者的模型、提示词、Skill、证据、校验和渲染规则不分叉，区别仅是本次模型调用使用的费用凭证。

## 有意不公开的实现细节

- 精确的系统提示词与 Skill 文本。
- 原书数据结构与导入方式。
- 召回、评分、组方和校验规则。
- 内部端点、请求头、限额实现与运维配置。
- 用于保护数据和防止滥用的具体措施。
