# 隐私与安全原则

## 用户自有 API Key

- 目前的自有 Key 能力仅面向支持的千问 API。
- Key 应只保存在当前浏览器标签页的会话存储中。
- Key 应仅作为单次请求的临时凭证传递给服务端。
- Key 不应写入业务数据库、用户档案、分析系统或应用日志。
- 官方托管与自有 Key 模式共用同一服务端提示词、Skill、证据和校验链路。

## 匿名体验

网站可使用不含个人信息的浏览器匿名标识，用于实现官方托管体验额度。服务端应只保存加盐哈希和必要计数，不保存浏览器中的原始标识。

该方式用于无登录体验，不等同于强身份认证，也不应宣称可以完全防刷。

## 服务端边界

- 私有数据表应由 RLS 或等价服务端权限保护。
- CORS 只是浏览器跨域边界，不能替代服务端鉴权、限额和输入校验。
- 密钥、内部提示词、数据检索结果与运维错误不应暴露给浏览器。
- 模型输出必须在服务端通过结构与业务规则校验后再进入正式渲染。

## 医疗内容边界

项目内容属于文化展示与知识参考，不用于代替个体化医疗诊断、处方或用药指导。
